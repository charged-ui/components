name: Dialog

description: Accessible modal dialog built on the native <dialog> element, with focus trapping, scroll lock, and light dismiss.

`<ui-dialog>` turns a native `<dialog>` you write into a modal: it wires up an
optional trigger, restores focus on close, locks body scroll, labels the dialog
from your title, and (optionally) closes on a backdrop click.

It’s built on the platform. Because the surface is a real `<dialog>` opened with
`showModal()`, the browser provides the hard parts for free — the **top layer**
(so the dialog escapes `overflow: hidden` and z-index), a genuine **focus
trap**, `role="dialog"` + `aria-modal`, initial focus on `[autofocus]`, and a
native `::backdrop`. Your markup stays in the light DOM, so it’s yours to style
with Tailwind utilities.

<Demo label="Basic dialog">
  <ui-dialog light-dismiss>
    <ui-button slot="trigger" data-variant="primary" data-size="small">
      <button>Delete project…</button>
    </ui-button>
    <dialog>
      <header slot="header">
        <h2 slot="title">Delete project</h2>
        <button slot="close" aria-label="Close dialog">
          ✕
        </button>
      </header>
      <div slot="body">
        <p slot="description">
          This permanently deletes the project and everything in it. This action
          cannot be undone.
        </p>
      </div>
      <footer slot="footer">
        <ui-button data-variant="secondary" data-size="small">
          <button data-dialog-close>Cancel</button>
        </ui-button>
        <ui-button data-variant="error" data-size="small">
          <button data-dialog-close>Delete</button>
        </ui-button>
      </footer>
    </dialog>
  </ui-dialog>
</Demo>

## Usage

Write a native `<dialog>` as a child of `ui-dialog`, and (optionally) a control
slotted into `trigger`. The component opens the dialog when the trigger is
clicked and adds all the modal behaviour — you never call `showModal()`
yourself.

The `[slot="header"]`, `[slot="body"]`, and `[slot="footer"]` slots are just
styled layout regions; every one is optional. Put your heading in a
`[slot="title"]` and the component links it as the dialog’s accessible name via
`aria-labelledby`; a `[slot="description"]` is wired to `aria-describedby`.

<ui-code-block
language="html"
code={`<ui-dialog light-dismiss>

  <button slot="trigger">Open</button>
  <dialog>
    <header slot="header">
      <h2 slot="title">Dialog title</h2>
      <button slot="close" aria-label="Close">✕</button>
    </header>
    <div slot="body">
      <p slot="description">Body content goes here.</p>
    </div>
    <footer slot="footer">
      <button data-dialog-close>Cancel</button>
      <button>Confirm</button>
    </footer>
  </dialog>
</ui-dialog>`}
/>

## Closing

Any element inside the dialog with a `data-dialog-close` attribute (or slotted
into `close`) closes it on click. `Escape` closes it too, and — when
`light-dismiss` is set — so does a click on the backdrop. Every path is
cancelable through the `ui-dialog-request-close` event.

A `<form method="dialog">` inside also closes the dialog on submit, the native
way — the component keeps its `open` state in sync.

## Triggers

The trigger can be any focusable control. A bare `<button>` works, and so does a
`<ui-button>` wrapper — the component wires ARIA (`aria-haspopup="dialog"`,
`aria-expanded`) and the click handler onto the focusable control inside it.

You can also skip the trigger entirely and drive the dialog yourself: set the
`open` attribute/property, or call `show()` / `close()` on the element.

<ui-code-block
language="js"
code={`const dialog = document.querySelector('ui-dialog');

dialog.show(); // open
dialog.close(); // close (fires ui-dialog-request-close first)
dialog.open = true; // or drive it as a property`}
/>

## Light dismiss

By default a click outside the dialog does nothing — the user must make a
choice. Add `light-dismiss` to let a backdrop click close it, which suits
non-destructive dialogs.

## Nested dialogs

Nest a `ui-dialog` inside another — put the child's trigger and `<dialog>`
right in the parent's body. Native `showModal()` stacks them, keeps focus in
the topmost, and makes the rest inert. The component adds the depth cue: the
parent slides back and shrinks while a child is open, and the child's own
backdrop is suppressed so the page behind is dimmed only once.

<Demo label="Nested dialogs">
  <ui-dialog light-dismiss>
    <ui-button slot="trigger" data-variant="primary" data-size="small">
      <button>View notifications</button>
    </ui-button>
    <dialog>
      <header slot="header">
        <h2 slot="title">Notifications</h2>
        <button slot="close" aria-label="Close dialog">
          ✕
        </button>
      </header>
      <div slot="body">
        <p slot="description">You’re all caught up. Good job!</p>
      </div>
      <footer slot="footer">
        <ui-dialog light-dismiss>
          <ui-button slot="trigger" data-variant="secondary" data-size="small">
            <button>Customize…</button>
          </ui-button>
          <dialog>
            <header slot="header">
              <h2 slot="title">Customize notifications</h2>
            </header>
            <div slot="body">
              <p slot="description">Review your settings here.</p>
            </div>
            <footer slot="footer">
              <ui-button data-size="small">
                <button data-dialog-close>Done</button>
              </ui-button>
            </footer>
          </dialog>
        </ui-dialog>
        <ui-button data-size="small">
          <button data-dialog-close>Close</button>
        </ui-button>
      </footer>
    </dialog>
  </ui-dialog>
</Demo>

The parent exposes `--nested-dialogs` (a count of how many dialogs are open
within it) and a `data-nested-dialog-open` attribute, so you can theme the
stacked look. Tune the depth cue with `--ui-dialog-nested-offset` and
`--ui-dialog-nested-scale-step`.

## Keyboard support

| Key                 | Action                                             |
| ------------------- | -------------------------------------------------- |
| `Escape`            | Close and return focus to the trigger              |
| `Tab` / `Shift+Tab` | Move between focusable elements (trapped natively) |
| `Enter` / `Space`   | Activate the focused control                       |

Focus is trapped inside the dialog by the native `<dialog>` element, and returns
to the control that opened it on close.

## Theming

Every surface is exposed as a custom property on the dialog, so a theme can
restyle it without touching the component. Utility classes and inline custom
properties override the defaults.

| CSS variable           | Purpose                    |
| ---------------------- | -------------------------- |
| `--ui-dialog-bg`       | Panel background           |
| `--ui-dialog-fg`       | Text colour                |
| `--ui-dialog-muted`    | Body / secondary text      |
| `--ui-dialog-border`   | Panel border               |
| `--ui-dialog-radius`   | Panel corner radius        |
| `--ui-dialog-padding`  | Header / body / footer pad |
| `--ui-dialog-width`    | Preferred width            |
| `--ui-dialog-shadow`   | Panel box shadow           |
| `--ui-dialog-backdrop` | `::backdrop` colour        |

Nested-dialog stacking is themable too:

| CSS variable                    | Purpose                                       |
| ------------------------------- | --------------------------------------------- |
| `--ui-dialog-nested-offset`     | How far a parent slides back per nested level |
| `--ui-dialog-nested-scale-step` | How much a parent shrinks per nested level    |

## Motion

The enter/exit fade-and-scale is CSS-only (`@starting-style` +
`transition-behavior: allow-discrete`) and is disabled for users with
`prefers-reduced-motion: reduce`.

## API

### `ui-dialog`

| Attribute       | Type    | Default | Notes                                           |
| --------------- | ------- | ------- | ----------------------------------------------- |
| `open`          | boolean | `false` | Reflected — set it to open/close, or read state |
| `light-dismiss` | boolean | `false` | Whether a backdrop click closes the dialog      |

| Method           | Notes                                                 |
| ---------------- | ----------------------------------------------------- |
| `show()`         | Open the dialog                                       |
| `close(reason?)` | Request close (fires `ui-dialog-request-close` first) |

| Slot          | Purpose                                                   |
| ------------- | --------------------------------------------------------- |
| `trigger`     | The control that opens the dialog (optional)              |
| `title`       | Heading used as the dialog’s accessible name              |
| `description` | Text wired to `aria-describedby` (optional)               |
| `header`      | Styled header row (optional)                              |
| `body`        | Scrollable body region (optional)                         |
| `footer`      | Styled footer for actions (optional)                      |
| `close`       | A control in the header that closes the dialog (optional) |

The dialog surface itself is the native `<dialog>` you write as a direct child.

| Event                     | Detail       | Notes                                         |
| ------------------------- | ------------ | --------------------------------------------- |
| `ui-dialog-open`          | —            | Fired after the dialog opens                  |
| `ui-dialog-close`         | `{ reason }` | Fired after it closes                         |
| `ui-dialog-request-close` | `{ reason }` | Cancelable — `preventDefault()` keeps it open |

`reason` is one of `close-button`, `backdrop`, `escape`, or `programmatic`. Any
element with `data-dialog-close` closes the dialog on click.
